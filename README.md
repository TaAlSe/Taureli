# Taureli — ядро для русских шахмат (таврелей)

Это MVP (минимально жизнеспособный продукт) десктопного приложения для игры в таврели. На текущий момент реализована полная логика ходов всех фигур, проверка легальности (с учётом шаха) и базовая структура для рокировки.

## Архитектура

Проект разделён на слои:
- **Core** — независимое ядро (фигуры, доска, генерация ходов, валидация, атака).
- **Data** — (пока пусто, для хранения партий).
- **UI** — (будет WPF-интерфейс, пока не реализован).
- **Tests** — юнит-тесты для Core.
- **Demo** — консольная демонстрация возможностей.

## Структура Core

### Папка `Board`
- `ChessBoard.cs` — класс доски 8x8.
  - Методы: `GetPiece` (с перегрузкой по `Position`), `SetPiece`, `Clear`, `ToString`.
  - Права на рокировку: `WhiteCanCastleKingSide`, `WhiteCanCastleQueenSide`, `BlackCanCastleKingSide`, `BlackCanCastleQueenSide`.
  - Метод `UpdateCastlingRights(Move move)` обновляет права после хода.

### Папка `Pieces`
- `PieceColor.cs` — enum (White, Black).
- `PieceType.cs` — enum с типами фигур таврелей (Volkhv, Horseman, Helgi, Knyaz, Ratoborets, Archer, Ratnik).
- `Piece.cs` — record (Type, Color) с методом `GetDebugCode()`.
- `PieceFactory.cs` — начальная расстановка (доска 8x8, row 0 = белые).

### Папка `Moves`
- `Position.cs` — record struct с координатами (Row, Col), методы `FromAlgebraic`/`ToAlgebraic`, свойство `IsValid`.
- `Move.cs` — **класс** (не record) с полями: `From`, `To`, `PromotionType`, `IsCastling`, `CastlingSide`. Переопределён `Equals`/`GetHashCode`.
- `Directions.cs` — статические константы направлений: `RookDirections`, `BishopDirections`, `QueenDirections`, `KnightDirections`.
- `LinearMoveGenerator.cs` — универсальный метод `GetMoves(ChessBoard, Position, directions, maxDistance)`.
- `PawnMoveGenerator.cs` — генерация ходов пешки (вперёд, двойной, взятие, превращение). Возвращает `List<Move>`.
- `CastlingMoveGenerator.cs` — генерация рокировок (использует права из `ChessBoard` и `AttackDetector`).
- `MoveGenerator.cs` — единая точка входа `GetMovesForPiece(ChessBoard, Position)`. Использует словарь направлений для линейных фигур и специальные вызовы для пешки, коня, хелги, короля (с рокировкой).

### Папка `Attack`
- `AttackDetector.cs` — статический метод `IsSquareAttacked(ChessBoard, Position, PieceColor)`. Проверяет атаку линейными фигурами, конём, королём и пешкой.

### Папка `Validation`
- `MoveValidator.cs` — статический класс.
  - `IsLegalMove(ChessBoard, Move, PieceColor)` — проверяет, не остаётся ли король под шахом после временного выполнения хода.
  - `GetLegalMoves(ChessBoard, Position, PieceColor)` — возвращает только легальные ходы для фигуры.

## Как генерируются ходы

1. Вызывается `MoveGenerator.GetMovesForPiece(board, from)`.
2. Определяется тип фигуры и цвет.
3. Для линейных фигур (ладья, слон, князь) — используются направления из словаря и `LinearMoveGenerator`.
4. Для пешки — специальный генератор `PawnMoveGenerator`.
5. Для коня — `LinearMoveGenerator` с `KnightDirections` и `maxDistance = 1`.
6. Для хелги — объединение ходов князя и коня.
7. Для короля — `LinearMoveGenerator` с `QueenDirections` и `maxDistance = 1` + рокировка (если доступна).
8. Результат — список объектов `Move`.

## Валидация легальности

- `MoveValidator.IsLegalMove` временно выполняет ход (учитывая превращение), затем проверяет, атакован ли король противником через `AttackDetector`.
- Если король не под шахом — ход легален.
- После проверки ход откатывается.

## Рокировка

- Реализована в `CastlingMoveGenerator`.
- Использует права из `ChessBoard`.
- Проверяет:
  - Король и ладья не двигались.
  - Клетки между королём и ладьёй свободны.
  - Король не под шахом и не проходит через атакованные поля.
- Возвращает ход с флагами `IsCastling = true` и `CastlingSide`.

## Тестирование

Все тесты находятся в проекте `Tests`. Используется xUnit. Покрытие:
- Начальная расстановка (`BoardTests`).
- Преобразование позиций (`PositionTests`, `MoveTests`).
- Генерация ходов всех фигур (ладья, слон, князь, конь, хелги, пешка, король).
- Проверка атаки (`AttackDetectorTests`).
- Валидация легальности (`MoveValidatorTests`).
- Рокировка (частично).

## Как запустить демо

1. Собрать решение.
2. Назначить проект `Demo` запускаемым.
3. Запустить — в консоли выводятся:
   - Примеры работы `Position` и `Move`.
   - Доска с начальной расстановкой.
   - Все возможные ходы для каждой фигуры на пустой доске (ладья, слон, князь, конь, хелги, пешка, король).

## План на шаг 2.2 – Особые правила пешки

### 2.2.1 – Хранение типа превращения в пешке
- Добавить в `Piece` поле `PromotionTarget` (тип фигуры, в которую превращается пешка).
- В `PieceFactory` определить для каждой пешки, перед какой фигурой она стоит, и задать `PromotionTarget` (для вертикали `e` – `Helgi`, для других – соответствующий тип).
- Обновить все вызовы конструктора `Piece` в тестах.

### 2.2.2 – Реализация превращения в `MakeMove` и `PawnMoveGenerator`
- При достижении последней горизонтали `PawnMoveGenerator` должен создавать ход с `PromotionType` из `PromotionTarget` (или `null`, если не задан).
- В `ExecuteMoveInternal` обрабатывать превращение (удаление пешки и установка новой фигуры).

### 2.2.3 – Взятие на проходе (en passant)
- Добавить в `ChessBoard` поле `LastMove` для хранения последнего хода.
- В `PawnMoveGenerator` проверять, был ли последний ход пешки на две клетки и стоит ли вражеская пешка рядом, и добавлять ход на проходе.
- В `ExecuteMoveInternal` обрабатывать взятие на проходе (удалять пешку, которая прошла мимо).

### 2.2.4 – Превращение при разделении башни (сложный случай, опционально)
- Если верхняя фигура башни – пешка, и она остаётся на последней горизонтали при разделении, она должна превратиться.
